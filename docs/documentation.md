# Generating the documentation {#documentation}

This documentation is generated by [Doxygen](https://www.doxygen.nl) from the XML documentation
comments in the source code and the Markdown pages in `docs/`.

## Commands

```powershell
# Windows (finds doxygen on PATH or in "C:\Program Files\doxygen\bin")
./scripts/generate-docs.ps1          # add -Open to open the result in the browser
```

```bash
# Bash (Linux, macOS, Git Bash)
./scripts/generate-docs.sh
```

```bash
# MSBuild: generate the docs after building DxfToRevit.Core
dotnet build DxfToRevit.Core -p:GenerateDocs=true
```

The output is written to `doxygen_out/html/index.html`; warnings go to
`doxygen_out/doxygen_warnings.log`. The `doxygen_out` folder is not under source control.

## Configuration

- `Doxyfile` — project settings. The Revit adapter is documented with `REVIT_API_AVAILABLE`
  defined, i.e. the variant that runs inside the add-in.
- `docs/*.md` — the guide pages; `docs/mainpage.md` is the start page.
- Diagrams: built-in class diagrams are always generated. Install
  [Graphviz](https://graphviz.org) and set `HAVE_DOT = YES` for collaboration, call and caller graphs.

## Documentation completeness

`Directory.Build.props` enables `GenerateDocumentationFile` for every production project. The
compiler therefore reports undocumented public members (CS1591) and broken `cref` references,
and the generated XML files provide IntelliSense in IDEs. A clean build has no documentation
warnings.
