# Revit add-in {#revit_addin}

`DxfToRevit.Addin` targets Revit 2025 (.NET 8). It compiles the `DxfToRevit.Revit` sources with
`REVIT_API_AVAILABLE`, so the adapter runs against the real Revit API.

## Ribbon

`DxfToRevitApplication` creates the **DxfToRevit** tab with the **DXF Import** panel:

| Button | Command | Purpose |
|--------|---------|---------|
| Import DXF | `ImportDxfCommand` | Imports walls and columns from a DXF file |
| Column Settings | `ColumnSettingsCommand` | Opens the settings dialog on its own (choose options, load families) |
| About | `AboutCommand` | Short description |

Icons exist in light and dark variants (`Resources/<Name>_<Light|Dark>_<16|32>.png`). The current
Revit theme is read at start-up and the icons are swapped when the `ThemeChanged` event fires.
The icons are generated by `scripts/IconGenerator`.

## Import settings

`ColumnImportSettingsForm` collects:

- **Import**: the categories to import (walls, columns, doors, windows, empty openings, with their
  counts in the DXF, `ImportCounts`) and whether elements already in the model are skipped;
- **Base Level** and **Top Constraint** (a level above the base, or *Unconnected*);
- **Unconnected Height** (only when the top constraint is *Unconnected*);
- **Circular columns** mode and family type (see @ref columns);
- **Other columns**: whether to import freeform columns and whether to build them as families.
- **Doors, windows and openings**: the **Opening types and heights...** dialog
  (`OpeningTypeMapForm`): the `TYPE` code → Revit type table and the default heights (see @ref openings).

Choices are remembered for the Revit session (`ImportSelectionPreferences`, `ColumnImportPreferences`,
`OpeningImportPreferences`).

## Import flow

1. DXF file selection and `DxfCenterLinePipeline.Analyze` (no files are written next to the DXF).
2. Settings dialog, with the door and window codes found in the DXF ready to be mapped. When the
   default opening heights are changed there, the DXF is analysed again.
3. Requests are built with the session options: wall types by thickness, column kinds and keys,
   opening types from the type map; only the chosen categories are kept.
4. Existing elements: `RevitExistingElementReader` reads the walls, columns, doors, windows and
   wall openings of the model and `ExistingElementMatcher` finds the requests they already cover
   (same level, same place, same kind; walls also the same thickness). Matching walls always host
   the doors and windows whose wall is not created now; when *Skip elements that already exist* is
   on, matching requests are not created and are counted in the summary.
5. `BuildingModelService` validates the requests and calls `RevitWallCreator`,
   `RevitColumnCreator` and, last, `RevitOpeningCreator` (openings need their host walls), which
   delegate to `RevitApiDocumentContext`.
6. All elements are written in one batch (`RevitImportBatch`, see *Batch writing* below) and
   committed once, as a single undo step, or rolled back when nothing could be created.
7. A summary dialog shows counts, elements already in the model, skipped ambiguous face pairs,
   grouped failures and notes, and
   opening markers that were not imported or have warnings.

### Batch writing

The import follows a *compute, then write* (unit of work) design: the pipeline and the request
factories compute every wall, column and opening first, without touching the document; only then
is the document changed, in one transaction:

| Step | What happens |
|------|--------------|
| `RevitApiDocumentContext.BeginBatch` | Opens one transaction with a failure preprocessor (`RevitBatchFailureHandler`) |
| Walls, columns, openings | Each element (and each new type) is written in its own `SubTransaction` (`RevitChangeScope`), so a failing element still rolls back alone |
| `RevitImportBatch.Regenerate` | Once after the walls, so columns join and openings find their hosts |
| Door flips | Collected while placing doors and applied together: one regeneration for all facings, one for all hands |
| `RevitImportBatch.Commit` | One commit: Revit regenerates and redraws once. Warnings are not shown one by one: `RevitWarningLog` collects them and the summary lists them grouped, overlaps first (overlapping walls, identical instances: usually the same drawing imported twice). Elements that cause errors are deleted and reported as failures with Revit's reason |

Before, every element committed its own transaction, so Revit regenerated the model and redrew the
view after each one; that per-element commit made the import slow. The same element code still
works outside a batch (it then opens its own transaction).

### Walls

Basic Walls are created on the base level with the unconnected height and base offset; with a
top level, the Top Constraint is set to it. Wall types are found by thickness in the requested
family (`Basic Wall` by default); when no type matches, a type is duplicated and its widest layer
resized (`RevitElementResolver.ResolveWallType`).

## Deployment

Building the add-in copies the DLLs, the icons and `DxfToRevit.addin` to
`%APPDATA%\Autodesk\Revit\Addins\2025`. Build while Revit is closed (the DLL is locked otherwise).
Override the destination with `-p:AddinDeployDir=<folder>` and the Revit installation with
`-p:RevitApiDir=<folder>`.

```bash
dotnet build DxfToRevit.Addin
```

For distribution to other computers, use the installer instead (see @ref installation);
build it with `-p:DeployAddin=false` so your own Revit folder is not touched.
